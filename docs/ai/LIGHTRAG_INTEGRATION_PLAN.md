# LightRAG Integration Plan

Phase 8A plan for integrating LightRAG graph-enhanced retrieval into WebHound AI Brain.

## What LightRAG Does

LightRAG extends retrieval-augmented generation with an explicit knowledge graph layer.
Instead of retrieving independent chunks, LightRAG builds entity–relationship graphs
from the corpus and uses graph traversal to find contextually connected answers.

For WebHound, this means:
- "Why does Cloudflare return 1020?" → finds Cloudflare docs + WAF policy docs + WADE FP rules, linked
- "What CWEs relate to missing headers?" → traverses CWE → taxonomy → scanner engine → evidence

## Integration Steps

### Step 1: Initialize LightRAG workspace

```python
from lightrag import LightRAG, QueryParam
from lightrag.llm import ollama_model_complete, ollama_embedding

rag = LightRAG(
    working_dir="./lightrag_workspace",
    llm_model_func=ollama_model_complete,
    llm_model_name="mistral",          # or any local LLM
    embedding_func=ollama_embedding,
    embedding_model_name="nomic-embed-text",
)
```

### Step 2: Ingest WebHound corpus

```python
import json

with open("corpus/exports/lightrag/lightrag_documents.jsonl") as f:
    docs = [json.loads(l) for l in f if l.strip()]

# Batch ingest (LightRAG handles entity extraction)
for doc in docs:
    rag.insert(doc["content"])

# Optional: preserve metadata via document IDs
```

### Step 3: Query

```python
# Naive RAG (vector similarity only)
result = rag.query("What causes Cloudflare 1020 errors?",
                   param=QueryParam(mode="naive"))

# Local graph traversal (entity-centered)
result = rag.query("What CWEs relate to missing CSP headers?",
                   param=QueryParam(mode="local"))

# Global graph (community-level summaries)
result = rag.query("What providers have WAF bypass risks?",
                   param=QueryParam(mode="global"))

# Hybrid (recommended for WebHound)
result = rag.query("Why does WADE suppress Cloudflare WAF findings?",
                   param=QueryParam(mode="hybrid"))
```

## Constraints

- **No cloud API**: Use a local LLM (Ollama + Mistral/Llama) for entity extraction
- **No customer data**: Only ingest from `corpus/` — never live scan results
- **Graph persistence**: Store the LightRAG workspace in `lightrag_workspace/` (gitignored)
- **Embedding model**: Use `nomic-embed-text` via Ollama, not OpenAI

## Relationship to Hybrid Retrieval

LightRAG complements (does not replace) the existing hybrid retrieval layer:

| Layer | Mechanism | Best For |
|-------|-----------|----------|
| Lexical | TF-IDF keyword matching | Exact term lookup |
| Dense | all-MiniLM-L6-v2 cosine | Semantic similarity |
| Hybrid | 0.35/0.65 weighted blend | General queries |
| LightRAG | Graph-enhanced traversal | Multi-hop reasoning |
